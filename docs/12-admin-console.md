# 管理员后台与节点状态

2026-11-18 的本地版本提供 `http://localhost:3100/admin`。ADMIN 登录后自动跳转，CUSTOMER 留在用户中心。所有 `/admin/*` API 统一执行会话与 ADMIN 校验；写请求仍校验浏览器 Origin。

## 可用功能

- 运营概览：五区控制就绪数量、订阅用户、已开通订阅、服务期用量、测试收款、待处理支付事件、最近操作。
- 区域节点：JP / SG / US / HK / TW 的地址、检测时间、最后就绪时间、SSH 隧道与引擎连接状态、Xray 版本；支持启用、停用、服务重启、重连控制隧道。
- 用户：分页与邮箱搜索，角色、订单数量、订阅状态，直达订阅管理。
- 套餐：创建、编辑、上架/下架；价格使用 USD，流量使用十进制 GB。只影响新订单；旧订单与 Stripe 续费合约保持冻结权益。
- 订单：分页/搜索，支付状态、支付方式、冻结金额、已付服务期。Stripe Sandbox 明确标记为测试金额。
- 订阅：状态、到期时间、已用/总流量、区域、采集时间、同步版本与错误；支持复制链接、暂停/恢复、重试同步和重置链接。
- 用量：用户本服务期累计用量与引擎报告的区域节点计数。节点计数可能包含独立 P0 身份；两者不可相加，不代表 Azure 计费流量。尚无按日历史用量账本。
- 操作记录：管理员、操作、对象、原因和时间；普通列表不返回密码摘要、加密凭证、访问 UUID、订阅 token、Stripe Checkout URL 或节点私钥。

## 状态与操作语义

`ready` 表示近期控制连接就绪，不能代替真实客户端出站测试，也不等同于 Azure VM 的电源状态。检测超过 120 秒显示过期，订阅下载不再使用该节点。界面每 10 秒刷新；worker 每约 30 秒采集节点及用户用量。

控制状态区分：控制就绪、隧道断开、引擎不可达、节点未连接、引擎缺少节点、检测过期、已停用及停用待确认。禁用的期望状态先落库；只有引擎确认停用后才显示“已停用”。失败停用由 worker 重试。节点动作使用数据库租约防止并发操作。

停用节点会停止该节点服务并从新 YAML 移除，**不会关闭或释放 Azure VM，也不会停止云资源计费**。控制连接短暂掉线不会删除用户已经购买的区域授权。所有授权区域停用时，引擎访问关闭，待再次启用后按原服务期恢复。

暂停订阅立即停止提供订阅下载，向引擎异步撤销访问。恢复要求仍有有效的已付服务期，不会重置到期日或流量。界面显示待同步状态，动作带版本检查，冲突返回 409。暂停不是取消 Stripe 续费；取消续费仍使用现有账户入口/API，后台未加入退款或真实资金操作。

复制链接为独立授权接口并留审计记录，不在列表返回 token。重置链接让旧 URL 立即失效，**已缓存 YAML 的访问 UUID 保持不变**；需要撤销访问时应暂停订阅。当前只验证撤销后不能建立新连接，未测量所有已有长连接的清退时间。

## 本次全部 false 的原因与修复

当时五条本机 SSH 控制隧道均已断开，引擎报主机转发端口 `ECONNREFUSED`。本机代理出口切换到了本项目 JP 节点，而 Azure 管理端口仍只允许原管理出口 IP，导致重建 SSH 失败。Azure 查询确认五台 VM 均为 running。

已使用既有、已获 NSG 放行的管理出口建立项目独立的本地运输进程，并绑定物理网卡，避免依赖当前所选 Azure 代理节点；保留 SSH 主机验证、原 NSG 范围及引擎 mTLS。worker 负责自动重连，后台也可手动触发。没有将服务停用实现为放宽防火墙。

同时修复 `ssh -f` 后台子进程继承 stderr 管道导致的假超时：启动时使用临时文件捕获错误，不再用 `PIPE/communicate` 等待常驻 SSH 的 EOF。失败检测与未知检测状态不再用一个无说明的 false 展示。

Mihomo 物理网卡绑定的配置依据：[官方代理通用字段](https://wiki.metacubex.one/en/config/proxies/#interface-name)。当前机器为 en0；迁移机器时必须检查实际网卡与管理出口。

## 验证记录

- 单元测试、TypeScript 检查、Next.js 生产构建。
- `pnpm test:admin`：所有管理端点未登录 401、普通用户 403、敏感字段不出列表、分页参数检查、冻结订单价格、并发订阅操作冲突、暂停/恢复引擎回读、旧链接失效与审计。
- `pnpm test:integration`：支付金额校验、并发重复发票只授予一次、真实引擎开通/撤销、五区授权与签名校验。
- 浏览器：管理员登录自动跳转；八个页面读取；套餐编辑保存；TW 节点停用→启用→恢复控制就绪；普通用户进入后台会回到用户中心。
- 控制隧道故障注入：单独断开 TW 隧道，worker 约 35 秒恢复。该耗时是本次观测，不是 SLA。
- Mihomo 绑定 en0 的独立客户端通过五个公网 REALITY 入口，请求 Cloudflare trace；JP / SG / US / HK / TW 出口 IP 与地区全部吻合。
- 暂停订阅后，旧 YAML 新建连接被拒绝，本次观测约 856 ms；未测试所有已有长连接。

本功能仍为本地 P0/P1。公网控制面、OIDC/MFA、更细团队 RBAC、网页录入 Azure 凭证与新增/销毁 VM、按日流量账本和正式收款尚未实现。当前后台管理已有节点和订阅，不冒充完整云编排控制台。
