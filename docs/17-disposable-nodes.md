# 节点释放、按区域启动与重建

节点是可丢弃的执行资源。用户、套餐、订单、订阅链接、接入身份、累计用量和期限保留在控制面；Azure 节点不保存业务数据库。新部署默认 `Standard_B2ats_v2`（2 vCPU / 1 GiB）+ 32 GiB `Standard_LRS`（Standard HDD），每个 Azure 区域的规格与容量仍需实际核验。

## 操作入口

管理员后台 → 区域节点：

- **选择区域启动**：列出 Azure 订阅的区域，可搜索、多选或一键选择 JP/SG/US/HK/TW。每个选择区域复用一台保留节点；没有记录时创建逻辑节点，已有机器时跳过，避免重复购买。每批最多 50 个区域，逐区记录失败原因。
- **停止并回收**：单台或批量执行。先从新订阅内容移除，再保存配置、停止代理、结算引擎已上报流量，最后释放 VM、磁盘、网卡、公网 IP、专属 VNet/NSG 和部署记录。全部确认不存在才显示“已回收”。
- **回收全部机器**：服务器在提交时固定当前未回收节点集合；正在部署或轮换等冲突任务会跳过并给出原因。失败的创建/重建任务可以选择回收残留资源。
- **启动 / 重建**：沿用区域、保存规格和 REALITY 接入参数，使用当前受控镜像与 32 GiB HDD，分配新公网 IP，自动安装、连接管理引擎、执行真实 Mihomo 出口 IP 验证，再发布到订阅池并同步用户权益。
- **重试回收 / 重建**：从持久化阶段继续，不会因为刷新页面创建第二台机器。同一批中某台失败不阻断其他节点。

原有“启用/停用代理”API 保留兼容，但已从默认维护菜单移除；用户可见的停止动作是释放资源。重启代理、重连管理隧道和 IP 轮换仍是独立维护操作。

## 保存和删除边界

`Node` 保存逻辑节点、地区与规格、接入参数及加密的 REALITY 私钥。`NodeLifecycle` 记录释放/重建阶段、资源清单、重试进度与审计。每次重建产生新的 `ProvisionOperation`，旧部署记录保留，旧任务无法重新启动已被回收或替换的机器。

删除适配器只处理连接配置中的订阅/资源组，并逐项检查 `managed-by=xray-zoo`、节点标签、VM/磁盘资源实例身份和网络绑定。P0 的短地区标签兼容；P0 未带标签的 deployment 只有在 `vmId` 输出匹配时才能清理。发现共享网络、额外数据盘、外部网卡绑定或资源被替换时，整个删除步骤停止。不会删除资源组，也不会递归删除其他业务资源。

磁盘和网卡可能随 VM 自动删除，重复执行把 404 视为完成；公网 IP 等残留仍会单独回收。回收任务未完成前仍可能产生部分费用。释放的是节点按需资源，控制面的数据库、Redis、备份和其他独立资源继续按其自身方式收费。

控制隧道有独立的已释放标记，健康检查不会重新连接旧 IP。重建的 SSH 主机密钥从受 Azure 身份验证保护的扩展结果获取，恢复隧道后才清除标记；保持严格 SSH 主机密钥检查，不关闭 TLS 校验。

## 订阅与规则

逻辑地区绑定不会随 VM 或公网 IP 变化：

| 规则 | 允许地区 |
|---|---|
| AI | JP、SG、US |
| Telegram 域名及 IP 段 | HK、TW |
| 通用流量 | 所有已就绪且有权限的节点 |

新 YAML 只包含已发布、启用、健康的节点。特定分组没有允许地区时使用 `REJECT`，不改走通用节点或直连。全部释放后暂时没有可下载的可用节点配置；重建完成后原订阅链接恢复供给，用户需要更新订阅，已缓存的 YAML 不会被服务端自动改写。

规则来源和合并优先级见 [规则说明](../packages/subscription/rules/README.md)。MetaCubeX 提供域名分类，Loyalsoldier 提供 Telegram CIDR；客户端每 24 小时获取维护中的上游规则。上游不能修改本项目固定的地区分组。

## 验证

- `pnpm test:lifecycle`：隔离数据库验证释放顺序、失败恢复、重复请求、配置与权益保留、重建代次、订阅池发布约束、按区域和全部回收批次。
- `pnpm test:azure`：内存 ARM 验证资源归属、实例替换、共享网络/外部绑定拒绝、删除顺序、404 重试与剩余资源检查，不接触实际 Azure。
- `pnpm test:provisioning` / `pnpm test:maintenance` / `pnpm test:ip-rotation`：部署、批量操作及 IP 轮换回归。
- `pnpm test` / `pnpm build:api` / `pnpm build:web` / `pnpm test:admin`：规则绑定、类型、构建、管理员权限与现有业务回归。

### 2026-11-18 实际验证

使用既有韩国 `xz-koreacentral-46a2157b` 完成一次真实回收和按区域重建。回收任务确认原 VM、系统盘、网卡、公网 IP、专属 VNet/NSG 与部署记录全部删除。重建后 ARM 核验为 B2ats_v2 + 32 GiB Standard HDD；真实 Mihomo 出口探测通过，六台节点恢复就绪。

两份有效订阅均验证：回收时移除韩国节点；重建完成后自动加入新地址；原链接和接入身份、额度与期限不变，累计用量不减少。其他五台原有机器没有迁移磁盘，下次回收重建时使用 HDD。全部回收按钮仅检查了预览，未停止整组业务节点。

合并后的完整订阅 YAML 通过本机 Mihomo `-t` 校验。上游检查时，MetaCubeX `meta` 分支更新时间为 2026-11-17，Loyalsoldier `release` 分支为 2026-11-16。后续由客户端按 provider 的 86400 秒间隔更新。
