# 产品范围与页面流程

更新：2026-11-18。状态：首版设计，用户已确认优先自营节点并向终端用户售卖订阅。

## 产品目标

让管理员在网页中完成云连接、选地区、建节点、发套餐，让用户完成注册、付款、导入订阅和续费。运营者能看到开通失败、节点健康、账单、用量和毛利，不依靠手工复制服务器配置维持业务。

首版是单运营商、多管理角色。数据保留 `operator_id`，但不提供多运营商入驻、独立收款、分账和品牌白标。网络流量直接经过地区节点，网页服务承载管理和订阅交付。

## 首版用户流程

### 管理员开通集群

1. 创建云连接，填写租户 ID、应用 ID、Azure 订阅 ID、授权资源组和 secret 或证书。
2. 验证身份、授权范围、区域、配额和凭证到期时间。结果显示每项是否满足，缺少权限时给出精确范围。
3. 选择地区、机器规格和数量。地区候选包括美国东部、日本东部、东南亚，以实际订阅查询结果为准。
4. 查看资源变更、预估固定费用、流量计价和总量上限，保存蓝图。
5. 提交创建任务，页面实时显示各地区创建、安装、注册、检测的进度。部分地区失败可单独重试。
6. 检测通过后将节点加入节点池，发布套餐。导出蓝图只含配置和秘密引用。

管理员看到的“已创建”与“可售”是两个状态。Azure VM 成功创建但 Xray 不可用的节点不能加入新订阅。

### 用户购买与使用

1. 邮箱验证并登录，选择显示价格、币种、地区、额度、周期和续费规则的套餐。
2. 跳转托管支付页；返回后看到付款确认与服务准备进度。
3. 后台确认付款且节点权益同步成功后，显示复制订阅链接、下载配置和导入客户端。
4. 用户中心显示有效期、用量、账单、节点可用地区、续费管理和链接重置。
5. 到期或额度耗尽后解释原因，并展示续费入口。恢复服务以后台确认后的权益为准。

## 页面清单

| 区域 | 页面 | 必须能完成的操作 |
| --- | --- | --- |
| 商城 | 首页 / 套餐 / 帮助 | 对比套餐，了解客户端支持，进入结账 |
| 用户中心 | 概览 / 订阅 / 用量 | 查看有效期、复制链接、重新生成配置 |
| 用户中心 | 账单 / 账户 | 下载渠道账单、管理续费、重置登录方式 |
| 管理端 | 经营概览 | 收入、已付未交付、活跃订阅、成本与异常 |
| 管理端 | 云连接 / 集群向导 | 凭证接入、资源预检、成本预览、部署与重试 |
| 管理端 | 节点 / 节点池 | 检测、发布、摘流、替换和删除 |
| 管理端 | 套餐 / 用户 | 版本化套餐、服务历史、按权限处理订阅 |
| 管理端 | 支付 / 对账 | 支付失败、退款、事件重放与差异处理 |
| 管理端 | 团队 / 审计 | 成员角色、敏感操作记录、凭证轮换 |

所有页面均需要空数据、加载、失败重试和无权限状态。节点操作展示任务进度及失败步骤；已付未交付不能伪装成“未付款”。

## 首版业务规则

- 每位用户同时持有一个有效服务订阅；允许多个历史服务周期和订单。
- 首发月付，单币种；年付、优惠券、余额钱包、代理分销和多币种延后。
- 流量按上传加下载计入套餐，展示单位 GB = 10^9 bytes；不宣传无限流量。
- 取消自动续费后保留已购周期；续费失败默认不赠送额外联网时长，既有周期到期才停用。
- 套餐变更下一周期生效，首版不处理即时按比例升级。
- 用户付款前检查至少有可售节点；付款后出现交付故障进入人工可见的补偿队列。
- 链接重置只更新配置获取凭证；疑似泄露选择“重置接入身份”，同时替换节点凭证并等待同步。
- 客服可协助定位问题；不能读取 Azure 凭证、重置用户接入身份或替用户决定退款。

## 后续范围

通过验证后扩展更多云供应商、多个运营商、企业 SSO、分账、自建轻量节点代理和更严格的设备管理。首版不将普通 Mihomo 的 HWID / UA 当成可靠设备限制，也不把 B 系列最大网络带宽当成每用户承诺带宽。

## 初期目标与验收口径

以下为工程目标，必须通过 P0/P1 测量，不能提前当作 SLA 对外发布。

- 基准测试先覆盖 3 个地区、3–10 个节点、100 个试用用户；商用容量由负载测试决定。
- 已验证付款到配置可用，在健康控制面与节点下目标 P95 小于 60 秒。
- 正常情况下停用同步目标 60 秒内；失联节点另行标记，不显示“全部撤销成功”。
- 部署任务可恢复且不会重复创建资源；每个长任务有稳定任务 ID。
- 用量显示附上最后更新时间；不把缺失样本当作零用量。
- 正式收费前完成完整退款、到期和凭证轮换演练。
