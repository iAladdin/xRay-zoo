# 交付顺序与验收

更新：2026-11-18。五区域部署、节点连接、Mihomo 出站和本地 Stripe Sandbox 最小闭环已验证。逐项结果见 [P0 验收记录](10-p0-results.md)。本文件保留完整阶段门槛，不能将局部通过理解为全部 P0 / P1 或正式运营验收通过。

## 0. 初始化（本次）

- Git 仓库、main 分支与 origin，首个提交。
- 产品范围、选型调研、领域词汇与架构决策。
- 数据/RBAC、Azure 编排、支付与订阅/API 契约。
- 集群蓝图、套餐及客户端配置占位模板。
- 检查文档链接、JSON/YAML 结构、模板占位符和 Git 变更。

## P0. 技术风险验证

优先验证决定架构能否成立的能力，再实现大量管理页面。预计 2–4 个工程日，仅作排序参考，遇到上游能力差异需重估。

| 实验 | 通过条件 | 不通过时 |
| --- | --- | --- |
| 固定 Remnawave / Node / SDK 版本 | 版本兼容、可创建/更新/查询用户与节点，重复 ensure 不多建用户 | 锁定另一稳定版本或验证 Marzban |
| 支付到账与事件处理 | 测试模式中乱序/重复事件只产生一份周期权益 | 先修状态机和唯一约束 |
| Mihomo 真机导入 | 配置校验、连接、自选地区与订阅刷新均可用 | 调整支持矩阵，禁止宣称所有 Clash 兼容 |
| 限额与重置 | 多节点合计计量正确，重启/重置/重试不会少计或重复计 | 修改 adapter；不能卖严格额度套餐 |
| 停用与已缓存配置 | 到期后旧 UUID 新连接失败，已有连接行为有实测记录 | 增加节点执行能力或降低可售承诺 |
| 面板/网络失联 | 确认本地到期、额度、数据丢失窗口与恢复行为 | 设计独立隔离流程，正式收费前解决 |
| 最小 Azure 授权 | 专用资源组创建成功，越界与角色分配失败 | 收敛或补充所需权限，记录原因 |
| 无秘密初始化 | 只有预期 VM 的 principal 可领取自己的初始化材料 | 修复绑定/令牌验证，禁止裸 token 引导 |
| 规格与成本 | 1/2 GiB 节点的内存、并发、持续吞吐和 credits 消耗有结果 | 升级规格、限售或更换节点方案 |

该阶段会产生云和测试流量费用。当前已按用户指令创建专用资源组中的五台 VM；费用、运行依赖和关闭方式见运行手册。

## P1. 跑通最小购买闭环

预计 5–8 个工程日，依赖 P0 引擎与计量可行。

1. 建 monorepo、固定依赖、数据库迁移、OIDC 与服务端权限。
2. 商城显示一个套餐版本，用户登录，测试支付结账。
3. Webhook inbox、事务 outbox、幂等 worker 与权益账本。
4. 一台手工准备的测试节点接入，adapter 创建身份和同步权益。
5. 用户复制自有域名订阅链接，在目标客户端联网。
6. 用量、到期、取消续费、续费失败、退款和链接/身份重置。

验收故事：同一笔付款回调重放十次仍只有一份周期；用户能联网；全额退款后缓存配置不能继续新建连接；恢复后不重复收费或扩额。

## P2. 网页自动创建多地区集群

预计 5–8 个工程日。

1. 云连接的 secret 与证书两种模式、到期提示、授权预检。
2. 地区/SKU/配额查询、Bicep 模块与费用计划。
3. 可恢复的资源创建、cloud-init、机器身份初始化、引擎注册与合成探测。
4. 按地区显示进度，部分失败重试，节点池发布与蓝图导出。
5. 摘流、替换、删除和遗留 IP/磁盘核对。

验收故事：创建美国/日本/东南亚候选集群，一地注入配额失败，健康地区保留；同 operation 重试不产生额外 VM；导出蓝图在新的专用资源组可重建同等拓扑。

## P3. 达到可收费运行要求

预计 4–7 个工程日，依赖实际渠道/域名/云环境可用。

- RBAC 越权验证，凭证轮换，日志 token/私钥脱敏验证。
- 上游升级回滚，灾难恢复、支付对账和节点失联演练。
- 托管/独立数据库备份与恢复；初始目标 RPO ≤ 15 分钟、RTO ≤ 4 小时，由实测校准。
- 计量误差和额度超用窗口有测量与预算；不满足约束的规格或地区不售卖。
- 用户帮助、发票/收据入口、客服退款流程、订阅刷新失败提示。
- 套餐定价、付款失败、取消和退款规则在结账前清楚显示。
- 小范围付费试运行，再扩大并发与地区；目标 SLO 以实测数据制定。

以上为约 16–27 工程日的初估，不是工期承诺，支付渠道开户、Azure 容量和上游能力缺口另计。

## 测试重点

- 领域规则：账期边界、月底、重复账单、旧事件晚到、退款归属、套餐版本。
- 集成：真实 PostgreSQL 唯一约束/outbox 恢复、上游 adapter 契约、Stripe 测试模式验签与对账。
- 故障：远端成功本地未记录、worker 崩溃、Redis 丢任务、ARM 超时、节点断网、云凭证过期。
- 用户验收：从浏览器付款到真实 Mihomo 连接；从退款到旧配置失效。
- 资源验收：同蓝图重放不会多创建，销毁后磁盘与 IP 不残留，不能删除不属于项目的资源。

## 尚需确定的业务输入

这些事项不阻塞本次设计，会影响实现上线配置。

| 输入 | 当前假设 | 何时确定 |
| --- | --- | --- |
| 收款主体与目标市场 | 自营，优先 Stripe 适配器 | 接入真实支付前 |
| 首发价格/币种/额度 | 单币种月付，示例不是正式售价 | 完成流量成本测试后 |
| 首发地区 | East US 2 / Japan East / Southeast Asia 候选 | 实际配额与用户线路探测后 |
| 域名与发信渠道 | app / sub 两个独立子域 | 用户内测前 |
| 身份提供方 | 标准 OIDC；Azure 环境可用 Entra External ID | P1 开始时锁定 |
| 上游许可与自有发布许可 | 无上游代码 fork，保留版本和许可信息 | 引入依赖及对外发布前 |
| 预算和最大规模 | 通过计划与实例上限控制 | 执行首个真实资源计划前 |
